## Dockerfile 国内镜像加速（部署 apt 层 45min 卡死）
- 现象：deploy.sh 构建镜像时 apt 层下载 ffmpeg 130+ 依赖包走 deb.debian.org，
  2742s 仍未完成（国内网络瓶颈）；web 阶段全部缓存命中，瓶颈只在 apt。
- 修复：Dockerfile 顶部加 ARG APT_MIRROR（默认 mirrors.ustc.edu.cn）与
  ARG PIP_MIRROR（默认 pypi.tuna.tsinghua.edu.cn/simple，stage 内重新声明）；
  apt 层先 sed 替换 /etc/apt/sources.list.d/debian.sources（trixie deb822 格式，
  兼容旧 sources.list）再装 ffmpeg；pip install 加 -i "$PIP_MIRROR"。
- 海外部署可用 build-arg 覆盖回官方源。原 apt 缓存失效是必然（Dockerfile 变了），
  换镜像后重跑 deploy.sh，apt 层预期几分钟内完成；此后该层再次进入稳定缓存。
- **复测失败 + 二次修复**：ARG 版实测 $APT_MIRROR 在容器 RUN 里展开为空，
  sed 把 deb.debian.org 替换成空串，URI 变 http:///debian（apt 显示 http:/debian），
  报 "does not have a Release file"。已核查 Dockerfile 是纯 LF、ARG 行完好，
  根因不明（ARG 传播怪象），不再深究。
- 最终方案：去掉全部 ARG，镜像源直接写死——apt 层用 RUN 内 shell 变量
  MIRROR='mirrors.ustc.edu.cn' + set -eux（构建日志会打印展开后的 sed 命令便于诊断）；
  pip 行直接写 -i https://pypi.tuna.tsinghua.edu.cn/simple。
  教训：部署脚本里少引入 ARG 间接层，写死即可。
