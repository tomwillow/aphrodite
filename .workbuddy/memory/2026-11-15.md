## 新增 Linux / Docker 部署链路

- 新增文件：`Dockerfile`（多阶段：node:22-alpine 打 `web/dist` → `python:3.12-slim` 运行时，`APHRODITE_DATA=/data`，`APP_HOST=0.0.0.0`，镜像 247MB）、`.dockerignore`、`docker-compose.yml`、`.gitattributes`（强制 `*.sh`/`Dockerfile` LF，避免 Windows 检出后在 Linux 上 `bad interpreter`）。
- 三个脚本 + 一个共用库：`scripts/build_image.sh`（构建）、`scripts/config_compose.sh`（交互式生成 compose）、`scripts/deploy.sh`（一键：构建→配置→`up -d`→等健康检查）、`scripts/lib/common.sh`（日志/颜色、`require_docker`/`init_compose`、`ask`/`ask_value`、校验函数、`yml_value`/`yml_port_spec`/`yml_data_dir`）。
- 关键设计：**compose 只引用 `image:`，绝不写 `build:`** —— 这是「跑完前两个脚本后，`docker compose up -d` 直接可用」的唯一前提。
- 交互默认值直接**从现有 `docker-compose.yml` 反向解析**（`yml_value` 等），不引入额外配置文件；这样手工改 compose 不会被覆盖，只会成为下次的默认值。改生成模板时要同步改这些解析函数。
- 交互提问固定从 `/dev/tty` 读，所以 `deploy.sh` 调子脚本、或 stdin 被管道占用时仍可交互；`-y` 可全非交互。
- `ask`/`ask_value` 带校验重问：端口 1-65535、并发正整数、地址只允许 `0.0.0.0`/`::`/IPv4，`127.0.0.1` 绑定用于只对本机开放（内容敏感，值得提供）。
- 验证方式：WSL Ubuntu-22.04 里（Windows 侧无 docker）复制源码到 `/tmp/aph`，`bash scripts/deploy.sh -y` 全链路跑通——镜像构建成功、`docker compose config -q` 通过、容器 `healthy`、`/api/health` 与 `/` 均 200、`data/` 落盘、重复 `docker compose up -d` 幂等。交互路径用 `script -qec` 造 pty 验证过（含非法端口重问）。
- 坑：Z: 是 CIFS `noacl` 挂载，shell 只能读、不能创建/删除目录；文件写入走 IDE 的 Write 才能落地，`mkdir` 也只在父目录已存在时成功。清理测试残留时 `rm` 会被 safe-delete 拦下并把失败原因吞掉，需查 `[SAFE_DELETE_FAIL_CLOSED]` 日志。
- 遗留小垃圾：`scripts/a.txt`、`scripts/lib/.probe`、`testprobe/`（探针文件，删不掉，需要用户在 Windows 侧手动删）。
